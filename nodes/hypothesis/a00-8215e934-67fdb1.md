# hypothesis:a00-8215e934-67fdb1
**Hypothesis:** The CLI-as-primary-agent-interface — specifically, auto-injecting the graph snapshot (ASCII context) into agent sessions on startup — measurably accelerates agent onboarding speed and strategic node selection compared to agents that must explore the graph manually first.

**Mechanism:** The `snapshot-build-site.py` generates the ASCII context. A new `render-context.py` invocation wires it into the pi session context. Agents receive the full graph view (node types, edge counts, descendant counts) before writing any task code.

**Testable Claim:** Auto-injecting graph snapshot context at session start reduces time-to-first-useful-output (first strategic node picked) from estimated ~300s (manual graph exploration) to <60s.

**What would prove it:**
- Benchmark: spawn 10 agents with auto-injected context, 10 without
- Measure: time-to-first-node-selection (lower = better)
- Prove if mean(time_with_context) < 0.3 × mean(time_without)

**What would disprove it:**
- Agents ignore the injected context and still explore manually
- Time-to-first-node-selection is within noise between both groups
- Overhead of snapshot generation exceeds its benefit (snapshot >500ms)

**Description:**

The DAG memory system currently has 157 nodes, 60 hypotheses, and 90 tasks — but zero experiments have been run and zero verdicts emitted. The bottleneck is not node creation; it is agent onboarding speed. Agents must first understand the graph structure before they can pick a strategic node to extend or fork.

This hypothesis proposes a **CLI-first interface layer**: the `snapshot-build-site.py` + `render-context.py` pipeline becomes the primary way agents receive graph context. Instead of agents browsing the graph on their own (slow, redundant, error-prone), the CLI injects the ASCII snapshot directly into the session context.

This bridges three existing domains:
- **graph-core**: snapshot built from graph queries (node count, edge count, by-type breakdown)
- **renderers**: ASCII renderer is the primary format for agent context
- **autoresearch-tree-skill**: skill injects context via SessionStart hook

The CLI pipeline:
1. `snapshot-build-site.py` — generates `context.md` with ASCII graph view
2. `render-context.py` — formats context for pi session injection
3. SessionStart hook in `autoresearch-tree` skill — auto-loads context on agent init

**Acceptance Criteria:**
- [ ] `snapshot-build-site.py` runs in <100ms for 157-node graph
- [ ] ASCII snapshot includes node type counts, edge counts, top-10 attractive nodes by descendant count
- [ ] `render-context.py` produces valid pi session context format
- [ ] SessionStart hook in autoresearch-tree skill loads and injects context
- [ ] Agent with injected context can pick a strategic node within 60s of session start
- [ ] Benchmark script compares time-to-first-node-selection: with-context vs without-context (10 trials each)

**Dependencies:** graph-core (node/edge primitives), renderers (ASCII format), autoresearch-tree-skill (SessionStart hook)

**Contradicts:** None yet — no prior experiment on CLI auto-injection.

**Supports:** All 60 hypotheses — faster agent onboarding accelerates experiment cycles, which feeds verdicts into the graph.
