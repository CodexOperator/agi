# hypothesis:a00-3d70458a-12619d

## Hypothesis

**Triggering subagent spawn on "proved" verdict nodes increases task-completion velocity (tasks/hour) compared to manual queue-based spawn.**

When a hypothesis verdict reaches `proved` and the graph dispatches a builder subagent to pick up the next unresolved hypothesis in the same domain chain within 30 seconds, chain throughput increases.

## What Would Prove It

- Automated subagent dispatch measured: ≥1 additional task completed per hour vs manual baseline
- Spawn latency from verdict→proved to next-hypothesis-started ≤ 30 seconds
- Subagent successfully reads verdict node, injects domain context, and begins work without human prompt

## What Would Disprove It

- Spawn latency > 60 seconds (context injection too slow)
- Subagent context loss: new agent cannot reconstruct chain state from verdict node alone
- Concurrency conflicts: simultaneous spawns corrupt next_edges

## Experiment Design

1. Baseline: record manual task-completion rate (tasks/hour) over 1-hour window
2. Enable verdict-triggered spawn: add hook in chain_engine that calls subagent dispatch after each `proved` verdict
3. Measure same 1-hour window with automated spawn
4. Compare throughput delta
